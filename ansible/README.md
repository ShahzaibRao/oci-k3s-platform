# Ansible — k3s cluster build

Ansible runs in **CI** (`.github/workflows/ansible.yml`, manual "Run workflow").
It never runs from a laptop — the SSH private key lives only in the
`ANSIBLE_SSH_PRIVATE_KEY` GitHub Secret.

## Layout

```text
ansible/
├── ansible.cfg          # inventory, roles path, CI-friendly SSH settings
├── inventory.ini        # AUTO-GENERATED by infra.yml — do not edit by hand
├── requirements.yml     # Galaxy collections
├── group_vars/all.yml   # pinned versions (k3s, cilium)
├── site.yml             # play order: common -> k3s_server -> cilium -> k3s_agent
└── roles/
    ├── common/          # OS prep (step 2)
    ├── k3s_server/      # k3s server + etcd, schedulable (step 3)
    ├── cilium/          # Cilium CNI, eBPF, Hubble (step 4)
    └── k3s_agent/       # join via node-token (step 5)
```

## Run it

GitHub → Actions → **ansible** → Run workflow. Watch the logs;
each role's real logic lands in its own step/PR.

## kubeconfig

Never committed, never uploaded as an artifact (this repo is public).
After k3s is up, grab it over SSH from WSL:

```bash
mkdir -p ~/.kube
ssh ubuntu@<server-ip> "sudo cat /etc/rancher/k3s/k3s.yaml" > ~/.kube/config
sed -i 's/127.0.0.1/<server-ip>/' ~/.kube/config
chmod 600 ~/.kube/config
```

`<server-ip>` is the `[k3s-server]` IP in `inventory.ini`.
